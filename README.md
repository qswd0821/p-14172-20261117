# p-14172-20261117

[slog.gg/p/14172](https://www.slog.gg/p/14172) 강의(레퍼런스 저장소 [jhs512/p-14172-2](https://github.com/jhs512/p-14172-2))를 참고해 만든 REST API 게시판입니다. 강의는 **38강까지** 진행한 시점을 기준으로 삼았습니다.

## 실행 방법

```bash
./gradlew bootRun
```

- 처음 실행하면 샘플 데이터(글 3건, 댓글 5건)가 자동으로 생성됩니다.
- H2 콘솔: http://localhost:8080/h2-console (JDBC URL `jdbc:h2:./db_dev;MODE=MySQL`, User `sa`, 비밀번호 없음)

```bash
./gradlew test
```

- 테스트는 `test` 프로필의 H2 메모리 DB를 사용하고, 각 테스트가 끝나면 롤백됩니다.

## API

| 기능 | 메서드 | 경로 | 응답 |
|---|---|---|---|
| 글 다건 조회 | GET | `/api/v1/posts` | `PostDto` 목록 |
| 글 단건 조회 | GET | `/api/v1/posts/{id}` | `PostDto` |
| 글 작성 | POST | `/api/v1/posts` | `201-1`, 전체 글 수 + 작성된 글 |
| 글 수정 | PUT | `/api/v1/posts/{id}` | `200-1` |
| 글 삭제 | DELETE | `/api/v1/posts/{id}` | `200-1`, 달린 댓글도 함께 삭제 |
| 댓글 다건 조회 | GET | `/api/v1/posts/{postId}/comments` | `PostCommentDto` 목록 |
| 댓글 단건 조회 | GET | `/api/v1/posts/{postId}/comments/{id}` | `PostCommentDto` |
| 댓글 작성 | POST | `/api/v1/posts/{postId}/comments` | `201-1`, 작성된 댓글 |
| 댓글 수정 | PUT | `/api/v1/posts/{postId}/comments/{id}` | `200-1` |
| 댓글 삭제 | DELETE | `/api/v1/posts/{postId}/comments/{id}` | `200-1` |

조회를 제외한 응답은 `RsData` 형식(`resultCode`, `msg`, `data`)이고, HTTP 상태코드는 `resultCode`의 앞자리를 따릅니다.

## 작업을 시작하고 진행한 과정

Claude Code와 함께 아래 순서로 진행했습니다.

### 1. 작업 환경 준비

- IntelliJ에서 Spring Boot 4.1.2 / Java 25 프로젝트를 생성했습니다(강의 1강과 같은 구성).
- `/setup-matt-pocock-skills`로 에이전트용 설정을 만들었습니다. 이슈 트래커는 로컬 마크다운(`.scratch/`), 트리아지 라벨은 기본값, 도메인 문서는 단일 컨텍스트입니다. 결과물은 `AGENTS.md`와 `docs/agents/`에 있습니다.

### 2. 요구사항 정리

처음 요구사항은 다음과 같았습니다.

- 샘플 데이터로 글 3건, 댓글 5건 자동 생성 (강의 3강은 댓글 3건이지만 5건으로 변경)
- 글 작성, 글 삭제, 댓글 작성, 댓글 삭제 기능과 각각의 테스트케이스
- 기능과 테스트를 추가할 때마다 설명을 담아 커밋하고, GitHub 새 리포지토리에 올리기

### 3. 설계 질문으로 결정 사항 확정

`/grill-with-docs`로 질문을 주고받으며 결정했습니다. 중간에 "38강까지만 진행했으니 39강 이후 내용은 빼자"는 기준이 생겨 질문을 다시 정리했습니다.

| 주제 | 결정 |
|---|---|
| 용어 | 글 = `Post`, 댓글 = `PostComment` ([GLOSSARY.md](GLOSSARY.md)) |
| 방식 | 화면 없이 JSON REST API만 제공 |
| 샘플 데이터 | 글이 0건일 때만 생성, 댓글은 1번 글 3건 / 2번 글 2건 / 3번 글 0건 |
| 범위 | 작성/삭제에 더해, 38강까지 자연스럽게 만들어지는 조회/수정도 포함 |
| 검증 | 제목 2~100자, 글 내용 2~5000자, 댓글 2~100자 |
| 글 삭제 | 달린 댓글도 함께 삭제 (`CascadeType.REMOVE`) |
| 실패 처리 | 404/400 예외 처리는 48강 이후 내용이라 제외, 테스트는 성공 케이스만 |
| 테스트 깊이 | 38강 수준: 상태코드, 실행된 컨트롤러/메서드, resultCode/msg, DB 상태와 응답 대조 |
| 작성자/인증 | 없음 |

### 4. 구현과 커밋

레퍼런스 저장소의 38강 시점 코드를 확인한 뒤, 정해 둔 순서대로 구현하고 커밋할 때마다 전체 테스트를 실행했습니다. 조회/수정은 따로 커밋하지 않고 관련된 작성/삭제 커밋에 함께 넣었습니다.

| 커밋 | 함께 들어간 것 |
|---|---|
| 초기 설정 | JPA/H2/validation, 엔티티, 샘플 데이터, RsData, ResponseAspect |
| 글 작성 기능 | 글 조회 |
| 글 작성 테스트 | 글 조회 테스트 |
| 글 삭제 기능 | 글 수정 |
| 글 삭제 테스트 | 글 수정 테스트 |
| 댓글 작성 기능 | 댓글 조회 |
| 댓글 작성 테스트 | 댓글 조회 테스트 |
| 댓글 삭제 기능 | 댓글 수정 |
| 댓글 삭제 테스트 | 댓글 수정 테스트 |

강의 코드와 다른 점:

- **댓글 작성**은 38강 시점 강의 코드에 없어서(56강 내용) 같은 스타일로 직접 만들었습니다. 댓글은 글을 통해 cascade로 저장되므로, 응답에 id를 담기 전에 `flush()`로 INSERT를 먼저 실행합니다.
- **삭제 테스트**는 응답만 보지 않고 JPQL로 DB의 댓글 수까지 확인합니다. 테스트는 롤백되기 때문에 응답만으로는 cascade 삭제와 orphanRemoval이 실제로 동작했는지 알 수 없습니다.
